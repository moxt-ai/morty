# Pair Morty

Connect this coding Agent to the user's existing Morty user and Machine.
Stop the original task; complete only this pairing in the current session.

Chat origin: {{BASE_URL}}

## Run

1. Identify the actual operating system, current shell, and original working directory.
   Keep Node, the Agent, and working directory in the same operating system. WSL is Linux;
   do not mix its executables or paths with native Windows ones.
2. Ensure Node.js 22.13.0 or newer, npm, and the latest `@moxt-ai/mobius` are installed.
   Choose your own harness: Codex = `codex`, Claude Code = `claude`, Pi = `pi`.
   Honor an explicit user choice.
   Complete its installation/authentication if needed; do not silently select another.
3. Take the one-use ticket from the supplied instruction URL. Download
   {{BASE_URL}}/setup.mjs to a private temporary directory, with a finite timeout
   and no redirects, and inspect it. Use commands appropriate to the current
   shell; stop if installation or download fails. Make the temporary directory
   private with native filesystem permissions.
4. Run the following command with real values and shell-appropriate quoting.
   Use the original absolute working directory, not the download directory.

```text
node <downloaded-setup.mjs> pair --base-url {{BASE_URL}} --cwd <absolute-current-working-directory> --token=<one-use-ticket> --harness <own-harness-id>
```

The script stores its configuration under the current user's `~/Documents` directory
and protects it using the operating system's filesystem permissions. Do not use a
repository as a substitute.
Pair always redeems its ticket and creates a fresh Runtime for that ticket's
Project and Machine; an expired or consumed ticket needs a new web instruction.
Mobius owns Runtime connection state and identifiers. Do not replace other
connections or save/back up Runtime or pairing identifiers yourself.
No separate prepare, bind, or finish command is needed.

## Finish

Keep progress in this session and wait for `status: "ready"` or an error (at most
five minutes). Intermediate runtime/binding messages are not completion. The
manager keeps the Runtime online after the command exits; a chat reply is a separate check.

Report: **Your Machine is connected. Return to your Morty page to start chatting.
Keep the Runtime online.** Include the returned URL, Machine ID, and working directory.
Do not generate an identity-transfer link or a text QR code.

On failure, use `error.code` and the private Runtime log. After `identity_ready`,
reconnect by following [setup]({{BASE_URL}}/setup.md) with your exact current session ID.
Fix installation/authentication for the selected harness; do not silently choose another.
Keep credentials private; never output tokens, pairing tickets, or private configuration.
