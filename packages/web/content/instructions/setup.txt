# Set up Morty

Connect this coding Agent to Morty so the user can continue the work in their browser.
Stop the original task; complete only this setup in the current session.

Chat origin: {{BASE_URL}}

## Run

1. Identify the actual operating system, current shell, and original working directory.
   Keep Node, the Agent, and working directory in the same operating system. WSL is Linux;
   do not mix its executables or paths with native Windows ones.
2. Ensure Node.js 22.19.0 or newer, npm, and the latest `@moxt-ai/mobius` are installed.
   Choose your own harness: Codex = `codex`, Claude Code = `claude`, Pi = `pi`.
   Honor an explicit user choice; never substitute another harness.
   Setup reads the current session from the harness itself; do not look up or ask
   for a session ID.
3. Download {{BASE_URL}}/setup.mjs to a private temporary directory, with a finite
   timeout and no redirects. Inspect it before running. Use commands appropriate
   to the current shell; stop if installation or download fails.
   Make the temporary directory private with native filesystem permissions.
4. Run the following command with real values and shell-appropriate quoting.
   Use the original absolute working directory, not the download directory.

```text
node <downloaded-setup.mjs> setup --base-url {{BASE_URL}} --cwd <absolute-current-working-directory> --harness <own-harness-id>
```

The script keeps this computer's Morty identity in the operating system's local
application data directory for the current user, which is not synced to other
computers, and protects it using filesystem permissions. Each computer has its own.
Do not copy it to a repository, a synced folder, or another computer.
The script reuses the saved identity and Machine for this origin and reconnects an
active managed connection when possible. If the saved Machine's Runtime is no
longer managed here, setup stops with `PROJECT_REPLACEMENT_REQUIRED` before replacing
anything. Explain in the user's language: **I cannot find this computer's original
connection configuration. Setting up a new connection will invalidate earlier
sharing links and browser access, and you will need to share a new link. Continue?**
Wait for explicit approval unless the user already authorized both the reset and
revoking earlier shared access. Merely asking to run setup or reconnect is not approval.
After approval, rerun the same command with `--replace-project <projectId>`, using
the exact `projectId` from `error.replacement`. Approval applies only to that Project.
Do not retry with this option automatically, delete local state, or create another
identity to bypass confirmation. If the user declines, stop and keep the saved state.
Approved replacement keeps the user, replaces the Project and Machine, and pairs a
new Runtime. Links and browsers from the replaced Project stop working.
Mobius owns Runtime connection state and identifiers; do not save or back them up yourself.
Normal setup and reconnection need no registration, separate bind command, or confirmation.

## Finish

Keep progress in this session and wait for `status: "ready"` or an error (at most
five minutes). The manager keeps the Runtime online after the command exits.
Only ready confirms setup; a working chat reply is a separate check.

Return the exact clickable `url` and the working directory from the `workspace` field. Display the owner-only PNG at
`qrPath` when present and inline images are supported; otherwise return the URL.
If `qrPath` is null, explain that the QR image is unavailable and use the link. Never open,
preview, or redeem the handoff URL yourself. Tell the user: **Open this link or
scan the QR code to chat. It is valid for 24 hours and
opens the same user and Machine. Keep the Runtime online. You can bind an account later.**
Also tell the user, in their language: **If you want to revoke these sharing links
later, come back and tell me: "Revoke all links I previously shared from this machine."
I can do that for you.** Include this reminder whenever you deliver a new sharing
link; knowing the command yourself does not replace telling the user.
When `project` is `"replaced"`, also tell the user, in their language: **This computer's
original connection configuration was missing, so setup started a new connection with your approval, and links and
browsers from this computer's earlier Morty setup stopped working. Use the new link.**

On `status: "replacement_access_revoked"`, immediately tell the user that earlier
sharing links and browser access have been revoked and the new connection is still
being set up. Do not wait for ready to report this access change.
On failure, also report `error.replacementAccess.message` when present. A `kind` of
`"unknown"` means the request may have revoked earlier access even though its reply
was not received; never say the old links are still valid. A `kind` of `"revoked"`
with `setupReady: false` means earlier access was revoked but the new setup is unfinished.
Keep the saved identity and continue recovery using the same approved Project when
approval is still required. Do not request a second approval for the same previously
authorized replacement, and never carry approval over to a different Project.

On failure, use `error.code` and the private Runtime log, and follow the `nextStep`
in `error.runtime`, `error.harness` or `error.binding` when present. Fix installation or
authentication for the selected harness; do not silently choose another.
Keep saved credentials private. Do not output tokens, pairing tickets, or private
configuration; only the ready handoff URL is intended for the user.

Managing previously shared access:
- When the user asks to revoke all previously shared access from this machine, run `node <setup.mjs> revoke-all-access`, as the same user on the same computer as setup. The command defaults to the origin in the saved local configuration; `--base-url <same Morty origin>` is optional and must match that saved origin. No harness, session ID, or workspace argument is needed. Use the deployment-owned setup download as above; never put local credentials in command arguments or output.
- This command uses the original locally saved identity, revokes previous sharing links and all other Morty credentials for its current Project (including recovery credentials), and retains the local identity so new sharing links can be created. It does not stop the daemon or its tasks. Already issued session access and open connections can remain usable until their access expires.
- Report success only after `status: "access_revoked"`. A missing local identity is an error; do not run setup or create a new identity to conceal it. This command is scoped to the Project saved in this local configuration, not other installations; a Project that setup replaced already ended everything shared from it.

Returning every Agent session to the computer:
- When the user explicitly asks to close or release every Morty Agent session so they can continue in the native Agent CLI or GUI, their request authorizes running `mobius quit` as the same operating-system user as setup. Do not ask for a second confirmation. This stops the Mobius manager and every active Runtime on this computer, including this session, but retains pairing and Agent-native history. Work still running in any session is interrupted.
- Before running the command, tell the user that this Morty connection will close and give recovery instructions in their language. Run the Agent CLI from the original working directory. Codex: `codex resume` opens its session picker; its GUI can be restarted and the conversation selected. Claude Code: `claude --resume` opens its picker, while `claude --continue` chooses the most recent conversation in that directory; restart its GUI and select the conversation if needed. Pi: `pi --resume` opens its picker, while `pi --continue` chooses the most recent session in that directory. A picker is safer than guessing a session ID. Tell the user that `mobius start` reconnects Morty later.
- After giving those instructions, run `mobius quit`. The command closes the Agent that invoked it, so disconnection is expected. Do not wait for another model turn, and do not report that the command completed after invoking it.
