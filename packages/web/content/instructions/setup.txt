# Set up Morty

Connect this coding Agent to Morty so the user can continue the work in their browser.
Stop the original task; complete only this setup in the current session.

Chat origin: {{BASE_URL}}

## Run

1. Identify the actual operating system, current shell, and original working directory.
   Keep Node, the Agent, and working directory in the same operating system. WSL is Linux;
   do not mix its executables or paths with native Windows ones.
2. Ensure Node.js 22.13.0 or newer, npm, and the latest `@moxt-ai/mobius` are installed.
   Choose your own harness: Codex = `codex`, Claude Code = `claude`, Pi = `pi`.
   Honor an explicit user choice.
   Use that harness's exact current session ID from its session metadata.
   Never guess, use the latest saved session, or substitute another harness.
   If the current ID is unavailable, ask the user for it before running setup.
3. Download {{BASE_URL}}/setup.mjs to a private temporary directory, with a finite
   timeout and no redirects. Inspect it before running. Use commands appropriate
   to the current shell; stop if installation or download fails.
   Make the temporary directory private with native filesystem permissions.
4. Run the following command with real values and shell-appropriate quoting.
   Use the original absolute working directory, not the download directory.

```text
node <downloaded-setup.mjs> setup --base-url {{BASE_URL}} --cwd <absolute-current-working-directory> --harness <own-harness-id> --session-id <exact-current-session-id>
```

The script stores its configuration under the current user's `~/Documents` directory
and protects it using the operating system's filesystem permissions. Do not use a
repository as a substitute.
The script reuses the saved identity and Machine for this origin and reconnects an
active managed connection when possible. When the saved Machine's Runtime is no
longer managed here, it keeps the user, replaces the Project and Machine, and pairs
a new Runtime.
Mobius owns Runtime connection state and identifiers; do not save or back them up yourself.
No registration, separate bind command, or replacement confirmation is needed.

## Finish

Keep progress in this session and wait for `status: "ready"` or an error (at most
five minutes). The manager keeps the Runtime online after the command exits.
Only ready confirms setup; a working chat reply is a separate check.

Return the exact clickable `url` and the working directory from the `workspace` field. Display the owner-only PNG at
`qrPath` when present and inline images are supported; otherwise return the URL.
If `qrPath` is null, explain that the QR image is unavailable and use the link. Never open,
preview, or redeem the handoff URL yourself. Tell the user: **Open this link or
scan the QR code to chat. It is valid for 24 hours and
opens the same user and Machine. Keep the Runtime online. You can bind an account later.**
Also tell the user, in their language: **If you want to revoke these sharing links
later, come back and tell me: "Revoke all links I previously shared from this machine."
I can do that for you.** Include this reminder whenever you deliver a new sharing
link; knowing the command yourself does not replace telling the user.

On failure, use `error.code` and the private Runtime log. Fix installation or
authentication for the selected harness; do not silently choose another.
Keep saved credentials private. Do not output tokens, pairing tickets, or private
configuration; only the ready handoff URL is intended for the user.

Managing previously shared access:
- When the user asks to revoke all previously shared access from this machine, run `node <setup.mjs> revoke-all-access --base-url <same Morty origin>`, using the same Documents directory as setup. No harness, session ID, or workspace argument is needed. Use the deployment-owned setup download as above; never put local credentials in command arguments or output.
- This command uses the original locally saved identity, revokes previous sharing links and all other Morty credentials for its current Project (including recovery credentials), and retains the local identity so new sharing links can be created. It does not stop the daemon or its tasks. Already issued session access and open connections can remain usable until their access expires.
- Report success only after `status: "access_revoked"`. A missing local identity is an error; do not run setup or create a new identity to conceal it. This command is scoped to the Project saved in this local configuration, not other installations or previously replaced Projects.
